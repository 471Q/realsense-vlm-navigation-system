1) REALSENSE DEPTH: FROM SENSOR TO DISTANCE AND LANES
-----------------------------------------------------
This section expands the full math and implementation details with concrete, numeric examples you can later convert to LaTeX.

1.0 Coordinate Systems and Calibration
- Depth frame provides a per-pixel range Z(u,v) in meters after applying the device scale; color frame is aligned to depth using RealSense alignment (so each RGB pixel corresponds to a depth pixel at the same (u,v)).
- Camera intrinsics (fx, fy, cx, cy) define the pinhole projection. For pixel (u,v):
  X = (u - cx) * Z / fx,  Y = (v - cy) * Z / fy,  Z = Z(u,v).
- Typical D435/D455 intrinsics at 640x480 are in the 5xx–6xx px range (verify with rs intrinsics). Use your actual calibrated values in experiments; all formulas below keep them symbolic.

1.1 Depth Units, Validity, and Masks
- Raw depth often arrives in millimeters; RealSense SDK exposes a depth_scale s (meters per unit). We use Z(u,v) [m] = raw(u,v) * s.
- Define a validity mask M(u,v) = 1 if Z_min ≤ Z(u,v) ≤ Z_max and Z(u,v) ≠ 0; else 0. We typically set Z_min ≈ 0.1 m, Z_max ≈ 6–10 m depending on sensor.
- Invalid values (0 or out-of-range) are excluded from statistics; medians are computed over valid subsets only.

1.2 Object Distance via Lower-Band Median (Conservative)
Problem: Averaging over full bbox biases toward torso/occluders, underestimating collision risk.
Solution: Use a lower vertical band of the bbox that corresponds to ground-contact adjacency.

Definition:
- Given bbox B = [x1, y1, x2, y2] (pixels) and a fraction α ∈ [0.25, 0.33], define the lower band:
  y_lower = y2 - α * (y2 - y1).
  R_lower = { (u,v) | x1 ≤ u ≤ x2, y_lower ≤ v ≤ y2 }.
- Collect depth samples S = { Z(u,v) | (u,v) ∈ R_lower and M(u,v)=1 } with optional subsampling stride s (e.g., take every s-th pixel to reduce cost).
- distance_m = median(S) if |S| ≥ N_min (e.g., N_min=20). Fallbacks if insufficient samples:
  1) Full-box median: R_box = { (u,v) | x1 ≤ u ≤ x2, y1 ≤ v ≤ y2 }, distance_m = median over valid samples.
  2) Nearest nonzero: search an expanded window B⊕Δ for the nearest nonzero Z; use that value.
  3) Sentinel: distance_m = Z_sent (e.g., 10.0 m) to avoid false STOP if no data.

Worked Example (replace with your intrinsics/data during write-up):
- Image size W=640, H=480. bbox B = [x1=180, y1=150, x2=260, y2=320]. α=0.30 → y_lower = 320 - 0.30*(170) = 320 - 51 = 269.
- R_lower spans 180≤u≤260, 269≤v≤320. Using stride s=2, suppose we obtain valid depths (meters):
  S = {0.89, 0.91, 0.90, 0.92, 0.00, 0.88, 0.93, 0.91, 0.90} → after removing zeros → S'={0.88,0.89,0.90,0.90,0.91,0.91,0.92,0.93}.
- distance_m = median(S') = (0.90+0.91)/2 = 0.905 m (use 0.91 m rounded for caption).
- If |S'| < N_min, we fallback as above.

Why Median?
- Median is a 50% breakdown estimator robust to salt-and-pepper noise and sparse zeros common in depth sensors near edges and reflective surfaces.

Pseudocode (reference to implementation median_depth_lower_band):
  function lower_band_median(Z, B, alpha, stride, N_min):
    y_lower = y2 - alpha*(y2-y1)
    S = []
    for v in range(ceil(y_lower), y2, stride):
      for u in range(x1, x2, stride):
        z = Z(u,v)
        if valid(z): S.append(z)
    if |S| >= N_min: return median(S)
    else: return fallback(Z, B)

1.3 Lateral Bearing and Pixel-to-Angle Mapping
- Center u_c = (x1+x2)/2. Horizontal angle θ_x (radians) = atan( (u_c - cx)/fx ). Degrees = θ_deg = θ_x * 180/π.
Numeric example: cx=320, fx=600 px, u_c=220 → δ=(220-320)/600=-0.1667 → θ_deg=atan(-0.1667)*57.3 ≈ -9.5°. Negative = left of center.
- For lane assignment, this exact angle is optional; comparing u_c to band edges suffices (see 1.6).

1.4 Corridor ROI Design (Where We Sample for Traversal)
- We focus sampling near the lower part of the frame to represent the immediate floor ahead of the device.
- ROI rows v ∈ [v_min, v_max] with v_min ≈ 0.55H and v_max ≈ 0.95H (tune per camera height and tilt). This biases statistics toward near-field navigation space.
- Optional downsampling stride s_ROI (e.g., 2–4) keeps computation linear and fast while preserving robust medians.

1.5 Three-Band Lane Partition and FOV Intuition
- Divide width W into three equal bands:
  LEFT:  0 ≤ u < W/3,  MID: W/3 ≤ u < 2W/3,  RIGHT: 2W/3 ≤ u < W.
- If the camera’s horizontal FOV is Φ (degrees), each band covers roughly Φ/3. For Φ≈69° (example), each band spans ~23°; MID ≈ [-11.5°, +11.5°] about the optical axis.
- This mapping helps you explain that a “clear MID” corresponds to a central corridor segment in physical space.

1.6 Lane Median Computation (with Robust Filtering)
For each band b ∈ {L,M,R}:
  - Collect depths within ROI ∩ band using stride s_ROI, filter by M(u,v)=1.
  - Optional robust trimming: compute p10 and p90 percentiles; keep only values in [p10,p90] to remove extreme outliers.
  - Z_b = median(kept samples). If no samples: mark band UNKNOWN; treat as BLOCKED for safety or borrow previous frame (see 1.9).

Example (ROI from v=264 to v=456, W=640):
  - LEFT median Z_L=2.30 m, MID median Z_M=0.90 m, RIGHT median Z_R=2.10 m.
  - With τ=1.8 m → clear(L)=True, clear(M)=False, clear(R)=True.

1.7 Clearance Threshold and Calibration
- Decision rule: clear(b) = [ Z_b ≥ τ ]. We use τ≈1.8 m as a conservative default for indoor corridors.
- Calibration procedure (recommended for PhD appendix): record Z_b across representative corridors; set τ to a lower quantile (e.g., 20–30th percentile) of “comfortable passing distance” distributions or tie τ to walker footprint + human stopping distance.
- You can also use intent-dependent τ (e.g., a stricter τ when moving faster).

1.8 Temporal Stabilization (Optional but Useful)
- Exponential moving average (EMA) on medians reduces flicker:
  Z_b,t = λ Z_b,t-1 + (1-λ) Z_b,t_raw, with λ ∈ [0,1). Larger λ → smoother but slower.
- Apply only when both current and previous medians are valid; else bypass to avoid lag after data dropouts.

1.9 Complexity and Performance Notes
- Lower-band median per detection is O(N_B/stride^2) over bbox pixels; lane medians are O(N_ROI/stride^2). Both are linear and inexpensive with moderate strides.
- Memory and CPU footprints are dominated by detector and image I/O; the depth math is negligible.

1.10 Failure Modes and Safeguards
- Reflective/absorptive surfaces produce zeros or jitter → median + validity mask mitigate; UNKNOWN bands treated as BLOCKED for safety.
- Floor slope or stairs: medians increase/decrease systematically across bands; your τ should still reflect safe traversal distance; consider EMA to damp rapid swings.
- Misalignment between color and depth: always align frames (RealSense rs.align) or run detection on the frame that depth is already aligned to.
- Holes near object edges: lower-band selection avoids upper-body artifacts and samples closer to the contact patch.

1.11 From Lane States to Suggestion (Pointer)
- Using clear(L/M/R), we derive Suggest deterministically (details in Section 1.6 and mapping in Section 1.7 example), e.g., (L=True, M=False, R=True) → mid-right; all three clear → continue; none clear → back.

Summary of Section 1
- We compute conservative object distances using a lower-band median; we compute robust lane medians over an ROI; we threshold to get CLEAR/BLOCKED per lane; and we feed these into a deterministic Suggest policy. Examples and pseudocode above match the implementation you can cite directly.

2) YOLOV8 + REALSENSE FUSION AND VLM FACT ENRICHMENT
----------------------------------------------------
2.1 Detection Pipeline
- Backbone/head: YOLOv8n (Ultralytics), using stride pyramid and decoupled head for objectness+class predictions.
- Preprocessing: RGB resized (e.g., imgsz 448), normalized; inference in FP16 if available to reduce latency.
- Output: For each detection d: class label c, confidence s, bbox (x1,y1,x2,y2).

2.2 Depth Association per Detection
- For each bbox, compute distance_m via lower-band median (Section 1.2).
- Determine which lane(s) the bbox intersects by comparing x-extent with lane boundaries; store binary flags.
- Compute bearing θ (optional) and a distance bin (near/med/far) using heuristics tied to τ (e.g., near < 0.6 m, caution < τ, safe ≥ τ).

2.3 Hazard Selection
- hazards = subset of detections with (distance_m below caution threshold) OR (intersecting chosen suggest lane) OR (large/fast-moving classes if available).
- Each hazard summarized minimally: {name, distance_m (rounded), lane_label} for caption.

2.4 Fact Packet for VLM
- We assemble a compact, structured textual description:
  - Lane medians: Z_L, Z_M, Z_R and their CLEAR/BLOCKED status.
  - Advisory level: SAFE / CAUTION / STOP from deterministic policy.
  - Chosen suggest token.
  - Hazard list (name + distance) only if CAUTION/STOP; suppressed for SAFE to keep caption short.
- This packet serves as ground truth for the caption, constraining the VLM to rephrase rather than invent.

3) VLM ARCHITECTURE AND REALSENSE AS VIDEO SOURCE
-------------------------------------------------
3.1 Qwen2.5-VL (3B) Overview
- Architecture (conceptual):
  - Vision encoder: ViT-like module producing patch embeddings from the input image.
  - Multimodal projection (mmproj): projects visual tokens into the LLM embedding space.
  - Language model: Decoder-only transformer, trained with instruction-following on multimodal data.
- The model is hosted behind an OpenAI-compatible endpoint via llama.cpp; we call chat/completions with image input.

3.2 RealSense as VLM Video Source
- The RealSense RGB frames act as the visual input; each processed frame is encoded to a supported format (JPEG/PNG) and embedded in the request.
- Multi-encoding fallback: To avoid occasional "failed to process image" errors, we try size/quality variants (e.g., JPEG q=70 at 224px, then PNG) until success.
- Frame cadence: We gate VLM requests with min_interval_s and a late_accept_s window to limit redundant updates and stabilize the UI.

3.3 Prompt Construction
- System message: Defines allowed Suggest tokens, one-sentence constraint, and safety semantics (e.g., include obstacles for CAUTION/STOP, suppress distances for SAFE).
- User message: Concise structured facts (lanes, advisory, hazards) + request for caption for a given intent (typically forward movement) with human-readable lane names.
- The VLM therefore acts as a constrained natural language renderer; the safety decision is made upstream by deterministic modules.

4) CAPTION POLICY: STRUCTURE, POST-PROCESSING, AND SAMPLE
--------------------------------------------------------
4.1 Policy Goals
- Guarantee one-sentence, human-friendly output with explicit Suggest token.
- Maintain semantic consistency: no STOP+continue contradictions.
- Safety: disclose obstacles/distances only when relevant (CAUTION/STOP), minimize cognitive load under SAFE.

4.2 Allowed Suggest Tokens
- {continue, left, right, stay-left, stay-right, mid-left, mid-right, left-right, back}

4.3 Post-Processing & Normalization
- Parse model output string; extract/normalize Suggest token to allowed set.
- If advisory == SAFE and model includes distances, strip them.
- If advisory == STOP, disallow any forward/continue phrasing; coerce Suggest to back if ambiguous.
- Humanize lane phrasing: replace internal tokens with "left/middle/right" language; avoid technical labels.
- Enforce final single sentence (collapse multiple sentences with commas; ensure trailing period).

4.4 Example System Prompt (Excerpt)
"You are assisting navigation. Follow these rules strictly:
- Output exactly one sentence.
- Always include 'Suggest: <TOKEN>' at the end, where <TOKEN> ∈ {continue, left, right, stay-left, stay-right, mid-left, mid-right, left-right, back}.
- If advisory is SAFE: do not mention obstacle distances.
- If advisory is CAUTION or STOP: mention the most relevant obstacle(s) with approximate distance (meters) and state the suggested lane.
- Use human terms (left, middle, right); avoid technical lane codes.
- Never output contradictory guidance (e.g., STOP with continue)."

4.5 Sample Input Facts to VLM
- advisory: CAUTION
- lanes: left=CLEAR(2.3 m), mid=BLOCKED(0.9 m), right=CLEAR(2.1 m)
- suggest: mid-right
- hazards: chair(0.9 m mid)
- intent: forward

4.6 Sample VLM Output (After Post-Processing)
"CAUTION: chair about 0.9 m ahead in the middle; path is clearer on the right-middle; Suggest: mid-right."

4.7 SAFE Case Example
Facts: advisory=SAFE; lanes all CLEAR (≥ 2.0 m); suggest=continue; hazards=[]
Caption: "SAFE: path looks clear to move ahead; Suggest: continue."

5) EDGE CASES, ROBUSTNESS, AND DESIGN TRADE-OFFS
------------------------------------------------
- Mirroring: With --mirror_view, swap left/right in lanes, hazards, and final text.
- Depth sparsity: If lower-band returns too few samples, fall back to box median; still robust via median.
- Rapid scene change: min_interval_s prevents spamming the VLM; late_accept_s provides a small window to accept improved phrasing.
- Composite tokens vs 5-sector lanes: Composite tokens retain nuance without overloading the UI; empirically reduced cognitive load while preserving guidance fidelity.
- STOP contradiction guard: If any STOP condition is true or no lanes are clear, force Suggest to back and remove forward intent wording.

7) SUMMARY
----------
The prototype fuses RealSense depth geometry and YOLOv8 semantics into a compact, deterministic scene model which the Qwen VLM converts into a single-sentence guidance caption. RealSense provides metric depth enabling conservative distances and lane medians; YOLO adds semantic labels; the lane-based policy turns continuous geometry into discrete, interpretable actions; and the VLM serves as a controlled linguistic surface, with strict post-processing to guarantee safety and readability.
