----------
This document explains my implementation in depth, focusing on: (1) how RealSense depth is captured and converted to distances and lane medians, (2) how YOLOv8 detections are fused with depth and fed into the VLM, (3) how the VLM architecture is used with RealSense as its video source, and (4) the policy (prompt + post-processing) that guarantees the caption’s structure and safety semantics. 1) REALSENSE DEPTH: FROM SENSOR TO DISTANCE AND LANES
-----------------------------------------------------
This section now zooms in further. For each core concept you get: Definition, Variables, Objective, Math, Problem Solved, Example, and Pseudocode (when helpful).

1.0 Coordinate Systems and Calibration
Definition: Mapping 2D pixel indices (u,v) of the aligned RGB-D frame to real-world 3D coordinates (X,Y,Z) relative to the camera.
Variables: u,v (pixel indices); fx, fy (focal lengths in pixels); cx, cy (principal point); Z(u,v) depth in meters.
Objective: Provide metric geometry for reasoning about object proximity and lane free space.
Math: X=(u-cx)*Z/fx, Y=(v-cy)*Z/fy, Z=Z(u,v). (Standard pinhole projection.)
Problem Solved: Without calibration, depth pixels are just scalar ranges. Projection lets us interpret spatial extent, if needed (e.g., footprint width).
Example: fx=615, fy=615, cx=320, cy=240; pixel (u=350,v=300) with Z=1.2 m → X=(350-320)*1.2/615 ≈ 0.0585 m right, Y=(300-240)*1.2/615 ≈ 0.117 m down, Z=1.2.
Pseudocode:
  project(u,v,Z,fx,fy,cx,cy):
    X = (u - cx) * Z / fx
    Y = (v - cy) * Z / fy
    return (X,Y,Z)

1.1 Depth Units, Validity, Masking
Definition: Converting raw sensor units into meters and filtering invalid or noisy depth samples.
Variables: raw(u,v), depth_scale s, thresholds Z_min,Z_max, validity mask M.
Objective: Ensure statistical operations (median) exclude zeros/outliers.
Math: Z(u,v)=raw(u,v)*s; M(u,v)=1 if Z_min ≤ Z(u,v) ≤ Z_max and Z(u,v)≠0 else 0.
Problem Solved: Removes corrupted readings (zeros on reflective surfaces, excessive range noise beyond sensor reliability).
Example: raw=800 (mm), s=0.001 → Z=0.8 m passes Z_min=0.1 and Z_max=6.0 → M=1.
Pseudocode:
  valid(z): return (z != 0) and (Z_min <= z <= Z_max)

1.2 Conservative Object Distance (Lower-Band Median)
Definition: Distance estimate focusing on the ground-contact region of a detected object.
Variables: bbox B=[x1,y1,x2,y2]; α (lower-band fraction); stride s; N_min (sample minimum); S sample set.
Objective: Produce a conservative (never too small) distance for collision risk.
Math: y_lower = y2 - α*(y2 - y1); R_lower = {(u,v)|x1≤u≤x2, y_lower≤v≤y2}. distance_m = median({Z(u,v)| (u,v)∈R_lower ∧ valid(Z)}).
Problem Solved: Full-box averages biased by upper-body surfaces; conservative ground-contact improves safety margin.
Example: α=0.30, box height h=170 → band height = 51 px. After filtering zeros, S'={0.88..0.93} → median ≈ 0.905 m.
Pseudocode:
  lower_band_median(Z,B,alpha,stride,N_min):
    y_lower = y2 - alpha*(y2-y1)
    S=[]
    for v in range(int(y_lower), y2, stride):
      for u in range(x1,x2,stride):
        z=Z(u,v); if valid(z): S.append(z)
    if len(S)>=N_min: return median(S)
    else: return fallback(Z,B)

Fallback Chain (Goal: never underestimate): full-box median → nearest nonzero → sentinel large distance.

1.3 Bearing (Horizontal Angle)
Definition: Angular offset of object center from optical axis.
Variables: u_c=(x1+x2)/2; δ=(u_c-cx)/fx; θ=atan(δ).
Objective: Provide lane-relative positioning; optional for lane assignment (band boundaries often enough).
Math: θ=atan((u_c-cx)/fx) * 180/π for degrees.
Problem Solved: Distinguishes left vs right occupancy; supports analytics for lane selection confidence.
Example: u_c=220, cx=320, fx=600 → δ=-0.1667 → θ≈-9.5° (left).

1.4 Corridor Region-of-Interest (ROI)
Definition: Subset of frame focusing on near-floor forward traversal zone.
Variables: v_min,v_max (fractional row bounds), stride s_ROI.
Objective: Reduce computation and concentrate on navigable space ahead.
Math: ROI={ (u,v)| v_min*H ≤ v ≤ v_max*H }.
Problem Solved: Ignores distant or ceiling regions irrelevant to immediate guidance.
Example: H=480, v_min=0.55→264, v_max=0.95→456.

1.5 Lane Partition & Field-of-View Mapping
Definition: Split image width into LEFT/MID/RIGHT bands approximating physical corridor segments.
Variables: W, band width w=W/3.
Objective: Discretize free space for simpler guidance decisions.
Math: LEFT:0≤u<w, MID:w≤u<2w, RIGHT:2w≤u<W.
Problem Solved: Reduces continuous geometry into interpretable actions and tokens.
Example: W=640 → w≈213 px → LEFT [0,212], MID [213,425], RIGHT [426,639].

1.6 Lane Median Computation (Robust Free-Space Depth)
Definition: Representative distance per lane using depth medians inside ROI.
Variables: For lane b: sample set S_b, optional trimming percentiles p_lo,p_hi.
Objective: Determine if lane has clearance beyond threshold τ.
Math: Z_b = median(S_b_filtered). clear(b) = (Z_b ≥ τ).
Problem Solved: Isolates lane-level obstruction signal despite depth noise.
Example: Z_L=2.30, Z_M=0.90, Z_R=2.10 with τ=1.8 → clear(L)=T, clear(M)=F, clear(R)=T.
Pseudocode:
  lane_median(Z,ROI,band):
    S=[]; for (u,v) in ROI∩band: if valid(Z(u,v)): S.append(Z(u,v))
    if len(S)==0: return UNKNOWN
    trim(S,p_lo=10,p_hi=90)
    return median(S)

1.7 Clearance Threshold τ and Calibration
Definition: Minimum median depth for a lane to be considered traversable.
Variables: τ, empirical dataset of corridor medians.
Objective: Balance safety margin and mobility efficiency.
Math: clear(b)= (Z_b ≥ τ). Calibration: τ = quantile_q( distribution_of_comfortable_pass_distances ).
Problem Solved: Converts raw metric differences into binary guidance states.
Example: Choose τ=1.8 m after analysis showing 80% of free corridors exceed 2.0 m median.

1.8 Suggestion Mapping (Deterministic Policy)
Definition: Mapping of lane clearance vector to action token.
Variables: c_L,c_M,c_R ∈ {0,1}.
Objective: Provide concise human action guidance.
Mapping Table:
  (0,0,0)→back
  (0,1,0)→continue
  (1,0,0)→left
  (0,0,1)→right
  (1,1,0)→mid-left
  (0,1,1)→mid-right
  (1,0,1)→left-right
  (1,1,1)→continue
Problem Solved: Eliminates ambiguity; forms stable interface to caption logic.
Pseudocode:
  suggest(cL,cM,cR):
    if cL==0 and cM==0 and cR==0: return 'back'
    if cL and cM and cR: return 'continue'
    if cM and not (cL or cR): return 'continue'
    if cL and not (cM or cR): return 'left'
    if cR and not (cL or cM): return 'right'
    if cL and cM and not cR: return 'mid-left'
    if cM and cR and not cL: return 'mid-right'
    if cL and cR and not cM: return 'left-right'

1.9 Temporal Stabilization (EMA)
Definition: Smoothing of lane medians across frames.
Variables: λ (smoothing factor), Z_b,t_raw, Z_b,t (smoothed).
Objective: Reduce flicker in suggestions due to transient sensor noise.
Math: Z_b,t = λ Z_b,t-1 + (1-λ) Z_b,t_raw.
Problem Solved: Prevents rapid oscillations (e.g., left ↔ mid-left) in borderline cases.
Example: λ=0.6, previous 2.0 m, raw 1.7 m → smoothed = 0.6*2.0 + 0.4*1.7 = 1.88 m (still clear if τ=1.8).

1.10 Complexity, Performance
Definition: Computational cost assessment.
Variables: N_B (bbox pixels), N_ROI (ROI pixels), stride factors.
Objective: Ensure real-time viability on embedded CPU/GPU.
Math: O(N_B/stride^2 + N_ROI/stride^2). Detector dominates overall latency.
Problem Solved: Justifies design choice of medians + strides vs dense point-cloud operations.
Example: ROI ≈ 640*200 ≈ 128k px; with stride=4 → 8k samples per frame; median O(n log n) trivial at this scale.

1.11 Failure Modes & Safeguards
Definition: Enumerated risks and mitigation strategies.
Variables: reflective surfaces, zero clusters, UNKNOWN flags, misalignment, extreme slopes.
Objective: Maintain safety despite sensor imperfections.
Math: Treat UNKNOWN as BLOCKED ⇒ clear(b)=False if Z_b=UNKNOWN.
Problem Solved: Avoid false SAFE due to missing data.
Example: If lane median sample set empty → Z_b=UNKNOWN → suggestion might shift from continue to mid-left/back depending on other lanes.
Pseudocode (UNKNOWN handling):
  if Z_b is UNKNOWN: clear(b)=False

1.12 Summary of Section 1
We defined all variables, showed conservative distance estimation via lower-band medians, converted spatial sampling into discrete lane states, and mapped them deterministically to guidance tokens. Each step emphasizes robustness (medians, masking, fallback) and interpretability (three bands, explicit policy) to build a safe foundation for caption generation.

2) YOLOv8 + REALSENSE FUSION AND VLM FACT ENRICHMENT
----------------------------------------------------
This section details how raw detections are produced, fused with depth, filtered into hazards, and serialized for the VLM.

2.0 Detector Overview
Definition: Single-stage, anchor-free object detector (YOLOv8n) producing class scores and bounding boxes across a feature pyramid.
Variables: imgsz (inference size), stride pyramid S∈{8,16,32}, confidence threshold τ_conf, IoU threshold τ_iou for NMS.
Objective: Efficient real-time detection to annotate the scene with semantic objects.
Math (post-process sketch):
  - For each location ℓ on each scale s∈S, prediction p_ℓ = (cx, cy, w, h, scores[classes]).
  - Convert center/size to corner bbox B=[x1,y1,x2,y2].
  - Filter by confidence: max(scores) ≥ τ_conf.
  - Non-maximum suppression: keep boxes with IoU < τ_iou relative to a higher-scoring box.
Problem Solved: Produces a compact, non-overlapping set of object proposals.
Example: imgsz=448, τ_conf=0.25, τ_iou=0.45 → typical output 5–15 boxes per frame in corridors.

2.1 Preprocessing and Inference
Definition: Prepare RGB for detector and run a forward pass.
Variables: imgsz, normalize mean/std, half-precision flag.
Objective: Minimize latency while preserving detection quality.
Steps:
  - Resize/letterbox to imgsz×imgsz.
  - Normalize to [0,1] and optionally standardize.
  - FP16 inference if supported.
Pseudocode:
  det_infer(rgb):
    im = letterbox(rgb, imgsz)
    im = im/255.0
    if fp16: im = im.astype(float16)
    preds = yolo.forward(im)
    detections = nms_and_decode(preds, τ_conf, τ_iou)
    return detections

2.2 Depth Association per Detection
Definition: Attach metric distance and lane occupancy to each bbox.
Variables: B=[x1,y1,x2,y2], distance_m (Section 1.2), lanes L/M/R boundaries, bearing θ.
Objective: Turn 2D detections into spatially meaningful facts for navigation.
Math:
  - distance_m = lower_band_median(Z,B,α) (Section 1.2).
  - lane flags: intersect(B, LEFT/MID/RIGHT) via x-overlap with band intervals.
  - bearing θ = atan((u_c-cx)/fx) (optional analytics).
Pseudocode:
  enrich_with_depth_and_lane(det, Z):
    det.distance_m = lower_band_median(Z, det.bbox, α, s, N_min)
    det.lane_flags = {L: overlaps(B,LEFT), M: overlaps(B,MID), R: overlaps(B,RIGHT)}
    det.bearing_deg = bearing(B, fx, cx)
    det.dist_bin = bin(distance_m; near, med, far)
    return det
Example: Box crosses MID and RIGHT; distance_m=0.95 m; dist_bin=near.

2.3 Hazard Selection
Definition: Choose a minimal, relevant set of obstacles to mention or to drive advisory.
Variables: caution radius r_c (≈ τ), stop radius r_s (< r_c), chosen suggest lane L*.
Objective: Prioritize obstacles that constrain the intended path.
Rules:
  - STOP if any det.distance_m ≤ r_s.
  - CAUTION if min distance in L* ≤ r_c or if a near object exists in adjacent band encroaching path.
  - SAFE otherwise.
Pseudocode:
  select_hazards(dets, suggest, r_c, r_s):
    hazards=[]; level='SAFE'
    for d in dets:
      if d.distance_m <= r_s: level='STOP'; hazards.append(d)
    if level!='STOP':
      for d in dets:
        if (lane_interferes(d, suggest) and d.distance_m <= r_c):
          level='CAUTION'; hazards.append(d)
    hazards = topk_by_distance(hazards, k=2)
    return level, hazards
Example: r_s=0.6 m, r_c=τ=1.8 m; a chair at 0.55 m triggers STOP; if closest is 0.95 m in MID with suggest=mid-right, CAUTION with that chair listed.

2.4 Fact Packet for VLM
Definition: Compact, deterministic summary sent alongside the frame.
Variables: Z_L,Z_M,Z_R, clear flags, advisory level, suggest, hazards[{name,dist,lane}].
Objective: Constrain the VLM to rephrase facts rather than invent.
Schema (textual example):
  advisory: CAUTION
  lanes: left=CLEAR(2.3), mid=BLOCKED(0.9), right=CLEAR(2.1)
  suggest: mid-right
  hazards: chair(0.9 mid)
Pseudocode:
  build_fact_packet(lanes, level, suggest, hazards):
    pkt = {
      'lanes': lanes_summary(lanes),
      'advisory': level,
      'suggest': suggest,
      'hazards': summarize(hazards)
    }
    return pkt
Problem Solved: Ensures the caption reflects upstream safety logic and lane truth.

3) VLM ARCHITECTURE AND REALSENSE AS VIDEO SOURCE
-------------------------------------------------
This section covers how Qwen2.5‑VL consumes frames + facts and returns a constrained caption.

3.0 Qwen2.5‑VL (3B) Dataflow
Definition: Multimodal LLM combining a vision encoder with a text decoder through a projection layer.
Variables: P (patch size), E_img (image embeddings), E_txt (text tokens), mmproj W_m (projection weights), context window T.
Objective: Produce a fluent caption consistent with provided facts.
Math (conceptual):
  E_img = ViT(image; P) → token sequence v_1..v_K
  T_img = W_m · E_img  (project to LM space)
  y = LLM([system, user(facts), image_tokens=T_img]) → text
Problem Solved: Translates visual cues + provided structure into human language.

3.1 RealSense Frames as Visual Input
Definition: RGB frames from RealSense fed as images to the multimodal endpoint.
Variables: encode type (JPEG/PNG), target size (e.g., 224), quality (e.g., q=70).
Objective: Ensure reliable ingestion despite occasional encoding issues.
Pseudocode (fallbacks):
  encode_image(frame):
    for (fmt, size, q) in [(JPEG,224,70),(JPEG,256,60),(PNG,224,None)]:
      try: return bytes_of(frame, fmt,size,q)
      except: continue
    raise EncodeError
Example: If JPEG@224@q70 fails, retry with PNG@224.

3.2 Cadence and Debounce
Definition: Rate-limiting and acceptance windows for stable UX.
Variables: min_interval_s, late_accept_s.
Objective: Avoid redundant updates; accept slightly-late improved outputs.
Pseudocode:
  should_send(now, last_sent, last_accept):
    if now - last_sent >= min_interval_s: return True
    if now - last_accept <= late_accept_s: return True
    return False

3.3 Prompt and Policy Injection
Definition: System/user prompts constrain output form and safety semantics.
Variables: allowed Suggest tokens, advisory level, lane summary, hazards list.
Objective: Make the LLM a linguistic compressor, not a decision-maker.
System Prompt (excerpt):
  - Output exactly one sentence.
  - End with 'Suggest: <TOKEN>' where TOKEN ∈ {continue,left,right,stay-left,stay-right,mid-left,mid-right,left-right,back}.
  - If SAFE: no distances. If CAUTION/STOP: include obstacle(s) + approximate meters.
  - Use human lane names only; avoid technical labels. No contradictions.
User Message: embed concise facts (lanes/advisory/suggest/hazards) + intent.
Example: advisory=CAUTION; lanes L=2.3 CLEAR, M=0.9 BLOCKED, R=2.1 CLEAR; suggest=mid-right; hazards=chair(0.9 mid).

3.4 Output Parsing and Normalization
Definition: Post-process model text to enforce the policy.
Variables: raw_text, parsed suggest token, advisory.
Objective: Guarantee single sentence, allowed token, and no contradictions.
Pseudocode:
  normalize_output(text, advisory):
    s = extract_suggest(text)
    s = coerce_to_allowed(s, advisory)
    if advisory=='SAFE': text = strip_distances(text)
    if advisory=='STOP': s='back'; text=remove_forward_intent(text)
    text = ensure_single_sentence(text)
    return finalize(text,s)
Problem Solved: Prevents unsafe or verbose outputs; aligns caption with our deterministic safety logic.

4) CAPTION POLICY: STRUCTURE, POST-PROCESSING, AND SAMPLES
---------------------------------------------------------
This section formalizes the captioning policy so it can be specified and verified.

4.1 Policy Goals
Definition: Constraints on the linguistic output to ensure safety, clarity, and brevity.
Variables: advisory ∈ {SAFE,CAUTION,STOP}, suggest ∈ allowed tokens, hazards list.
Objective: Produce exactly one sentence that communicates risk and action succinctly.
Problem Solved: Prevents verbose or contradictory guidance that increases cognitive load.

4.2 Allowed Suggest Tokens
Set S = {continue, left, right, stay-left, stay-right, mid-left, mid-right, left-right, back}.
Rationale: Covers single-lane and two-lane composite actions plus a safe retreat.

4.3 Structural Constraints and Grammar
Definition: Output grammar G enforcing one sentence and token at end.
Rules:
  - Exactly one sentence (no hard line breaks; one final period).
  - If advisory=SAFE: do not include numeric distances or hazard names.
  - If advisory∈{CAUTION,STOP}: include 1–2 key hazards with approximate meters.
  - Append 'Suggest: <TOKEN>.' where <TOKEN>∈S.
Example SAFE: "SAFE: path looks clear to move ahead; Suggest: continue."
Example CAUTION: "CAUTION: chair about 0.9 m ahead in the middle; Suggest: mid-right."

4.4 Normalization Pipeline
Pseudocode:
  finalize_caption(facts, raw_text):
    s = extract_suggest(raw_text)
    s = coerce_to_allowed(s, facts.advisory)
    text = raw_text
    if facts.advisory=='SAFE': text = strip_distances_and_hazards(text)
    if facts.advisory=='STOP': s='back'; text=remove_forward_intent(text)
    text = humanize_lanes(text)  # "middle" not technical tokens
    text = enforce_single_sentence(text)
    return ensure_trailing_period(text_with_suggest(text,s))
Problem Solved: Guarantees compliance even if the model deviates slightly.

4.5 Example System Prompt (Fuller Excerpt)
"You are assisting navigation. Follow these rules strictly:
- Output exactly one sentence.
- Always end with 'Suggest: <TOKEN>' where <TOKEN> ∈ {continue, left, right, stay-left, stay-right, mid-left, mid-right, left-right, back}.
- If advisory is SAFE: do not mention obstacle distances or object names.
- If advisory is CAUTION or STOP: mention the key obstacle(s) with approximate distance in meters and state lane preference.
- Use human terms (left, middle, right); avoid technical lane codes.
- Never output contradictory guidance (e.g., STOP with continue)."

4.6 Input/Output Samples
Input facts:
  advisory=CAUTION; lanes L=2.3 CLEAR, M=0.9 BLOCKED, R=2.1 CLEAR; suggest=mid-right; hazards=chair(0.9 mid)
Output (normalized):
  "CAUTION: chair about 0.9 m ahead in the middle; Suggest: mid-right."

4.7 Contradiction Precedence
Rule: STOP > CAUTION > SAFE. If STOP, force suggest='back' and remove any forward-continue phrasing.
Rationale: Safety-first invariant in linguistic layer.

5) EDGE CASES, ROBUSTNESS, AND DESIGN TRADE-OFFS
------------------------------------------------
5.1 Mirroring
Definition: Horizontal flip semantics for cameras mounted with mirrored view.
Variables: flag --mirror_view.
Objective: Keep perceived left/right consistent between UI and caption.
Behavior: Swap LEFT↔RIGHT in lane stats, hazards, and suggestion tokens; humanization reflects swap.

5.2 Depth Sparsity and Dropouts
Definition: Insufficient valid Z samples in a region.
Mitigation: Fallback chain (lower-band → full box → nearest nonzero → sentinel). UNKNOWN bands treated as BLOCKED.
Trade-off: Conservative bias may reduce aggressiveness but increases safety.

5.3 Rapid Scene Changes and Debounce
Definition: Frequent detection/lanes oscillations under borderline thresholds.
Mitigation: min_interval_s + EMA smoothing on medians; late_accept_s allows improved caption shortly after prior one.

5.4 Composite Tokens vs. Fine Sectors
Definition: mid-left/mid-right/left-right tokens vs 5-sector overlays.
Rationale: Composite tokens preserve actionable nuance while keeping UI simple (3 bands) and captions readable.
Observation: Reduced cognitive load in informal tests; aligns with single-sentence policy.

5.5 Contradiction Guard (Safety Invariant)
Rule: If STOP or no lanes clear → suggest='back' and remove forward intent in caption.
Pseudocode:
  if level=='STOP' or (not cL and not cM and not cR):
    suggest='back'; caption=remove_forward_intent(caption)

5.6 Performance and Resource Budget
Detector dominates latency; depth medians and normalization are O(N) with stride. Prefer FP16 and small imgsz when constrained; ensure clarity remains sufficient for object classes of interest.

7) SUMMARY
----------
The prototype fuses RealSense depth geometry and YOLOv8 semantics into a compact, deterministic scene model which the Qwen VLM converts into a single-sentence guidance caption. RealSense provides metric depth enabling conservative distances and lane medians; YOLO adds semantic labels; the lane-based policy turns continuous geometry into discrete, interpretable actions; and the VLM serves as a controlled linguistic surface, with strict post-processing to guarantee safety and readability.
